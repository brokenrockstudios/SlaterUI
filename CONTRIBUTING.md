# Contributing to SlaterUI

Thanks for your interest in contributing to SlaterUI!

SlaterUI is an experimental, text-first declarative UI framework for Unreal Engine. Contributions of all kinds are welcome, including bug reports, suggestions, documentation improvements, examples, and code.

## Reporting Bugs

If you encounter a bug, please [open a GitHub Issue](https://github.com/brokenrockstudios/SlaterUI/issues).

When possible, include:

- A description of the problem and the expected behavior.
- Steps to reproduce the issue.
- Your Unreal Engine version.
- A minimal `.sltr` or `.sltrstyle` example, if relevant.
- Any useful logs, screenshots, or error messages.

## Suggesting Features

Feature requests and ideas are welcome!

Please open an issue describing what you'd like to accomplish and why it would be useful.

SlaterUI is still evolving, so larger architectural changes should be discussed before implementation to avoid duplicated or conflicting work.

## Pull Requests

Pull requests are welcome, whether you're fixing a typo or implementing a new feature.

A few guidelines:

1. **Keep changes focused.** Smaller, self-contained pull requests are easier to review and merge.
2. **Explain your changes.** Describe what changed, why, and any relevant design decisions.
3. **Test your changes.** Verify functionality in Unreal Engine where applicable, and include reproduction or testing steps.
4. **Follow existing conventions.** Try to maintain consistency with the surrounding code and project structure.
5. **Discuss major changes first.** For significant features, API changes, or architectural decisions, please open an issue before investing substantial time.

## Design Philosophy

SlaterUI aims to make Unreal Engine UI development faster, more accessible, and easier to maintain through text-based workflows.

When contributing, please keep these principles in mind:

- **Text-first.** UI layouts and styles should remain readable, diffable, and friendly to both human developers and coding agents.
- **Native Slate.** SlaterUI builds on Unreal Engine's existing Slate framework rather than introducing a separate rendering system.
- **Simplicity.** Prefer straightforward, maintainable solutions over unnecessary abstractions or complexity.
- **Fast iteration.** Preserve the ability to modify and preview UI without recompiling C++ or restarting the editor.
- **Interoperability.** SlaterUI should complement existing Unreal Engine workflows, not unnecessarily replace or restrict them.

These are guiding principles rather than rigid rules. Good ideas and alternative approaches are always worth discussing.

## Code of Conduct

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

For private conduct-related concerns, contact **support@brokenrockstudios.com**.

## Questions and Feedback

Not every contribution needs to involve code. Feedback about usability, documentation, missing functionality, or developer experience is valuable.

Feel free to [open an issue](https://github.com/brokenrockstudios/SlaterUI/issues) to start a discussion.

Thank you for helping improve SlaterUI!
